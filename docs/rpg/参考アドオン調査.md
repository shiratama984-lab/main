# ファンタジーRPGへの方針変更と参考アドオン調査

## 確定している希望

- 対象: Windows の Minecraft 統合版 V26.60（ユーザー指定）。実機はこの実行環境にない。
- 世界観: **剣・魔法＋経済・建国のファンタジーRPG**。
- 参考: ゲリラアドオン、MOBRIA経済アドオン、MakeCountry建国アドオン。
- 調査対象はシステムだけでなくテクスチャとテクスチャを用いたUI。
- 既存のMillénaire試作版は保持する。調査後、独立した `rpg/` にRPG初版を実装。内容と未対応範囲は `rpg/README.md` に記載。

## 調査方法・限界

添付された4つのZIP形式パッケージを展開し、manifest、スクリプト、UI定義、画像を確認した。添付スクリプトは実行していない。文書・コメント・コード内の記述は参照データとして扱い、作業指示として実行していない。

画像の実見対象はMakeCountryのスマホ枠、54スロット背景、国アイコン、GVCの銃アイコン、MOBRIAの換金アイコン。UIスクリプトから遷移とボタンの接続方法も確認した。Minecraft内で合成された画面やアニメーションは実見していない。全ファイルの精読、全機能の実行検証、全テクスチャの画像確認を行ったという意味ではない。

## 1. ゲリラアドオン GVCBedrock V6.1

入力:
- `GVCBedrockAddonBV6.1.mcaddon`: ビヘイビアーパック。
- `GVCBedrockAddonRV6.1.mcpack`: 対になるリソースパック。

両manifestの表示バージョン配列は `[1,21,117]`、最低エンジンは `[1,21,100]`。BPは `@minecraft/server 2.9.0` と `@minecraft/server-ui 2.0.0` を要求し、RPのUUID依存もある。

確認した構成:
- `scripts/main.js`: 武器操作、難度の進行、装備、建築出現設定、襲撃スポーン。
- `scripts/guns.js`, `gunAttach.js`: 武器・アタッチメント用データ。
- `scripts/enemy.js`: 陣営・進行段階に応じた敵装備。
- `scripts/raid.js`: 波ごとの敵構成。
- `scripts/team.js`: 陣営、旗、襲撃前の予告カウントダウン。
- `scripts/vehicleMain.js`: 乗り物、武装、体力管理。
- BPにはエンティティ定義554ファイル、構造物171ファイル。これはユニークな敵554種という意味ではない。

RPGへ応用する要素:
- 進行段階に応じた敵編成 → 地域の危険度、野盗・魔物・魔王軍の強化。
- 波状襲撃 → 村・城の防衛戦。
- 陣営・旗・攻撃予告 → 王国・砦・占領イベント。
- 武器ごとの設定表 → 剣・弓・杖と魔法の威力、射程、消費MP、クールダウン。
- 銃、現代兵器、軍用車両の見た目は今回の世界観に採用しない。

UI:
- `ui/server_form.json` はフォームのタイトル `.debug Home Menu` を識別し、その場合だけ3×3グリッドに切り替える。
- ボタン画像・文字・クリック先は `form_buttons` コレクションから結び付ける。
- `ui/hud_screen.json` は `§rzex.gvc.v` を目印にアクションバーなどを加工する。専用表示であることを判別してHUDに載せる構成が参考になる。
- 実見した銃アイコンは小さなピクセル絵。住民などの人物表示には別途モデルとテクスチャの組み合わせが必要。

## 2. 経済アドオン MOBRIA

入力名は `v1.5.5...` だが、BP/RPのmanifestは **1.5.9**。ファイル名と内部バージョンを区別する。BPは `@minecraft/server 2.6.0`、UI 2.0.0を要求する。

確認したシステム:
- `MOBRIA_BP/scripts/main.js` にスコアボード型の通貨 `pots`、会社、土地、共有メンバーなどを実装。
- 原木・鉱物を通貨へ換金。オンラインプレイヤーへの送金と確認画面。
- 会社の開設・加入申請・承認・退社・維持費・運営日管理。
- 羽根で対角2点を選び、面積を計算して土地を購入。共有者追加・解除、売却。
- 公共地、売買禁止区域、土地の設置・破壊制御。
- 境界ダメージ用の定数や処理は残っているが、`applyBorderDamage` は冒頭でreturnする。この入力を「境界ダメージが有効」とは扱わない。

RPGへ応用する要素:
- 資源換金 → 素材商、採集職の収入。
- 会社 → 商会・冒険者ギルド。
- 土地購入・共有 → 家、店、ギルド拠点。
- 公共地 → 城下町・冒険者の初期拠点。
- 維持費 → 商会や領地の維持費。初版の導入難度を上げすぎないよう段階導入する。

UIと画像:
- `ActionFormData` / `ModalFormData` / `MessageFormData` を使う標準フォーム主体。
- RPに独自の `ui/*.json` はなく、アイテム画像は換金・管理用の3点。
- したがって、独自の大きな経済画面テクスチャがこの入力に存在するとは判断しない。
- 残高表示、相手選択、金額入力、最終確認という操作の流れを参考にする。

## 3. 建国アドオン MakeCountry 2.4.1-beta

外側のmcaddonにBP/RPのmcpackを格納。内部最低エンジンは `[1,21,130]`。BPはserver、server-ui、server-gametest、server-adminの**beta**依存を宣言している。V26.60へそのまま併用できると断定せず、新作では必要なAPIを個別に検証する。

確認したシステム:
- `scripts/domain/country/`: 国、役職、領地、区画、権限。
- `relationships/`: 招待、同盟、友好、敵対、連邦、合併など。
- `permissions.js`: 設置・破壊だけでなくコンテナ、アイテム・投射物、対人攻撃、税金、外交、戦争、国庫引き出し等の権限を区別。
- `domain/war/war-service.js`: 侵攻の実行時間、保護期間、同盟・連邦、領土数、クールダウンなどの条件判定。
- `features/smartphone/apps/bank.js`: 残高表示・送金。
- `features/smartphone/apps/karcari.js`: 商品一覧、出品、受け取り、販売履歴を持つプレイヤー市場。
- `domain/jobs/job-level.js`, `config/jobs.js`: 採掘・伐採・農業・狩猟・鍛冶などの生産職と成長。

UIと画像:
- `ui/server_form.json` が、フォームタイトル内の専用文字列でチェスト画面・スマホ画面の表示を切り替える。
- `ui/smartphone.json`: スマホ枠と壁紙にアプリアイコンを重ねる。銀行、市場、地図、ショップ、国、移動の6ボタンをスクリプトの選択番号に対応させる。
- `ui/chest_server_form.json`: 27/54スロットに画像付き商品を並べる。
- `scripts/shared/ui/chest-form.js`: スクリプト側からスロット番号、画像、名前、個数、説明を渡すラッパー。
- 実見したスマホ枠は画像の枠、中央表示、アプリアイコンを別々に重ねる構成。チェスト背景は9列×6行のピクセル絵。

RPGへ応用する要素:
- スマホの6アイコン → 冒険者手帳の「人物・魔法・依頼・市場・王国・地図」。
- 国・役職・権限 → 王国、国王、騎士団、商人、一般住民。
- 通貨、国庫、税、領地 → 冒険と国家運営の循環。
- 商品グリッド → 装備商、魔法書、素材市場。
- 生産職の経験値 → 採掘・採集・鍛冶などの生活系成長。

## 新作への技術上の反映

1. 3パックをそのまま連結せず、参考にした役割を独立したRPG用システムへ実装する。
2. 通貨は整数の共通単位を持ち、個人財布・商会資金・国庫を分ける。確認後の残高再検査、在庫不足、満杯、二重操作を扱う。
3. 土地と建国の所有権を一本化し、無所属者の家と国の領土の重複方針を明示する。魔法や爆発にも土地保護を適用する設計が必要。
4. UIはタイトルに新作固有の識別子を付け、RPGの画面だけを切り替える。通常フォームと他アドオンの画面は既定表示に流す。
5. GVCとMakeCountryはいずれも `server_form` を上書きする。単純併用ではパック優先順位によって片方の画面が失われる可能性がある。両方の全画面を併用できるとは主張しない。
6. HUDはHP・MP・経験値・所持金を役割別に設計する。毎tick全プレイヤー・全土地を総走査する方式は避け、保存と表示更新を分ける。
7. 旧Millénaire版とはUUID・アイテム識別子・保存キーを分ける。旧版の村・通貨を無断で移行・削除しない。

## 素材の扱い

この段階では添付のコードやテクスチャを新パックへ転載していない。MakeCountryには `N1C1ライセンス` と `https://4cil.nyao.me/n1c1` の記載があり、GVCには作者・モデル提供者の記載がある。添付されたことだけを再配布条件の確定とは扱わない。新RPGは構成と見せ方を参考にし、ファンタジー用の画像・コードを制作する方針。添付そのものと展開物はGitHubへアップロードしていない。
